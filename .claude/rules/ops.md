# Operations

- Env: Lean per `lean-toolchain` (elan, or a system Lean of that exact version on `PATH`); `pnpm install --frozen-lockfile` (Node per `.node-version`, dev-only tooling); `bash tools/fetch-tools.sh` (betterleaks, zizmor, actionlint pinned by sha256 in `tools/tools.lock` → `.tools/bin/`); `pnpm exec playwright install chromium-headless-shell`; system `bwrap`, `shellcheck`, `jq`, `clang` (static analyzer). Re-pin a scanner: `bash tools/pin-tool.sh <name> <version>` (rewrites all four platform lines + digests).
- Gate = `bash tools/gate.sh`: the ONE invocation; CI (`.github/workflows/gate.yml`) runs exactly it. Stages run to completion, each `<stage> rc=N <s>s` (suites add their three slowest areas), close `gate rc=N <s>s`: `tools` (fetch) · `lean-style` · `lean-build` (every target; proofs kernel-checked; `warningAsError`) · `lean-test` (`lake test`) · `lean-pure` (`TestPure.lean` interpreted = the mutation tool's suite; an FFI call there aborts it) · `cli` (`tests/cli/smoke.sh`: the built binary — data folder from the environment, exit codes, nothing written outside the data folder) · `examples` (`fvtrace check --strict` on both examples) · `trust` (`tools/trust.sh`: `fvtrace-trust` audit + independent-kernel replay) · `c-analyze` (`clang --analyze` on the FFI shim) · `vendor` (`tools/vendor-hacl.sh --verify`: vendored HACL* = the pinned release) · `js-format` (Prettier) · `js-lint` (oxlint typed + DOM-sink ban, stylelint, html-validate) · `js-types` (`tsc -p . | web | tests/e2e`) · `js-test` (schema ↔ decoder cases, GUI palette floors, Renovate extraction) · `e2e` (Playwright + axe against the built `fvtrace serve`) · `audit` (no Lake packages + `pnpm audit`) · `secrets` (betterleaks: history + working files) · `workflows` (zizmor + actionlint) · `spec` (`.agent/spec-lint`) · `shell` (shellcheck) · `meta` (version in `Fvtrace/Version.lean` = `lakefile.lean`).
- Fast gate (iteration, never the claim) = `bash tools/fast-gate.sh [--e2e]`: cheap stages in parallel + incremental Lean build + tests; prints the stages it skipped.
- `green` = the stages run + passed; skipped, not-run + missing checks reported by name or `none`.
- Probes = `bash tools/gate-probe.sh [probe…]`: every purpose-built check (`lean-style`, `meta`, `fvtrace-trust` detection paths, the replay log policy, the Lake-manifest audit, the CLI smoke via `FVTRACE_SMOKE_BIN` = a binary that ignores `FVTRACE_HOME`, `lean-pure` via an FFI call planted in `TestPure.lean`, `assets` = the GUI's verdict words ≠ the engine's + an assumed result in the skill's example trace) plants a failing input + demands its named cause; a new purpose-built check ships its probe in the same commit. Upstream tools (Lean kernel, oxlint, tsc, Prettier, stylelint, html-validate, axe, pnpm audit, betterleaks, zizmor, actionlint, shellcheck, spec-lint) carry their own suites; a config change to one of them proves firing on a planted input in its commit body.
- CI: `gate` job (ubuntu) = `tools/gate.sh`; `portability` job (macOS, Windows) = `lake build` + `lake test`. Every `uses:` pinned by full SHA, `contents: read`, `persist-credentials: false`. Update automation = Renovate (`renovate.json`): npm, Actions digests, `lean-toolchain`, `tools/tools.lock` versions (digests via `tools/pin-tool.sh`).
- Commit body records the red witness for each new test: the mutated or unfixed revision + the command + its failing output; a test pinning already-passing tested (unproved) code instead records `node tools/mutate.mjs <file>` scope + every survivor with its ruling.
