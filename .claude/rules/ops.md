# Operations

- Env: Lean per `lean-toolchain` (elan, or a system Lean of that exact version on `PATH`); Node per `.node-version` (dev-only tooling); `bash tools/bootstrap.sh` = the locked Node packages + the scanners `tools/tools.lock` pins by sha256 (betterleaks, zizmor, actionlint → `.tools/bin/`) + Playwright's Chromium, each step quick once in place; system `bwrap`, `shellcheck`, `jq`, `clang` (static analyzer); Python ≥ 3.10, `curl`, `tar`, `git` (the page engine build: `lake build` fetches the pinned Emscripten + Lean runtime sources into `.lake/build/wasm/` and generates Init's C once per toolchain, minutes; law = `.claude/rules/wasm.md`).
- Gate = `bash tools/gate.sh`: the ONE invocation; CI (`.github/workflows/gate.yml`) runs exactly it, one parallel job per shard (`--shard <name>`; `STAGES` atop the script gives each stage its shards; each job = a fresh checkout ⇒ every shard whose stages read the build lists `lean-build`). Stages run to completion, each `<stage> rc=N <s>s` (suites add their three slowest areas), close `gate rc=N <s>s`; the read-only checks in `TOGETHER` (they need neither the build nor the fetched tools) run side by side beside the others, each log printed whole (`together_start` / `together_finish`, shared with the fast gate; probe `together`): `tools` (fetch) · `lean-style` · `lean-build` (every target, the page engine + `fvtrace-wasm` included; proofs kernel-checked; `warningAsError`) · `lean-test` (`lake test`) · `lean-pure` (`TestPure.lean` interpreted = the mutation tool's suite; an FFI call there aborts it) · `cli` (`tests/cli/smoke.sh`: the built binary — data folder from the environment, exit codes, nothing written outside the data folder) · `examples` (`fvtrace check --strict` on both examples) · `engine` (`node --test tests/engine/`: the exported page's WebAssembly engine, run by its loader, answers every differential case byte for byte as the native engine does, with nothing on standard error; Chromium = e2e `engine.spec.js`) · `trust` (`tools/trust.sh`: `fvtrace-trust` audit (claims, axioms, escape hatches, OS capabilities) + independent-kernel replay + the self-trace's statement replays (`fvtrace verify --run` on a copy: a failed replay writes its notice into the trace it reads); both skipped for a key = export sha256 + `lean --version` + `tools/trust.sh` + `.lake/build/bin/fvtrace` sha256 (the replay consumer) + the self-trace + `TrustMain.lean` + `tools/statement.sh` that already passed, recorded in `.lake/trust/replayed` after a pass) · `c-analyze` (`clang --analyze` on the FFI shim + the page engine bridge) · `vendor` (`tools/vendor-hacl.sh --verify`: vendored HACL* = the pinned release) · `js-format` (Prettier) · `js-lint` (oxlint typed + DOM-sink ban, stylelint, html-validate) · `js-types` (`tsc -p . | web | tests/e2e`) · `js-test` (schema ↔ decoder cases, GUI palette floors, Renovate extraction) · `e2e` (Playwright + axe against the built `fvtrace serve`) · `audit` (no Lake packages + `pnpm audit`) · `secrets` (betterleaks: history + working files) · `workflows` (zizmor + actionlint) · `fanout` (every stage has a shard; the `gate.yml` matrix = the `STAGES` shards; one `--shard "$SHARD"` step) · `spec` (`.agent/spec-lint`) · `shell` (shellcheck: `*.sh` + every other file whose shebang names sh or bash, i.e. `.agent/spec-lint`) · `meta` (version in `Fvtrace/Version.lean` = `lakefile.lean`).
- Step ledger (template `Gate command` + `Gate usefulness`) = `.gate/ledger.tsv` (gitignored; `GATE_LEDGER` = another file, empty = none): `tools/gate.sh` + `tools/fast-gate.sh` append one row per stage per run + the run's total, `tools/ci-gate.sh` one per CI job (its stages stay in the CI history) = date · tree (the working tree's content, `HEAD^{tree}` when clean) · run (`gate[:<shard>]` | `fast` | `ci:<run id>`) · step · seconds · verdict (`green` | `red`). Each red is classified on the spot, before any rerun: `bash tools/gate-ledger.sh classify STEP product|gate|flake|planted [RUN]` (an appended row; `tools/gate-ledger.sh` alone lists the unclassified reds, rc 1 while any; `summary` = per step: runs, seconds, reds by class). A `gate` or `flake` red = a gate bug: its fix = the next unit (a `Tasks` row after the current one). Probe `ledger`.
- CI gate (template `CI gate`) = where the full gate runs while `main` CI is green: commit, then `bash tools/ci-gate.sh <unit>` in the background (pushes `HEAD` to `ci/<unit>`, waits for that commit's run = every shard + portability, prints run id + tree + each job's wall-clock, appends the jobs to the ledger, deletes the branch when green). Red → each red job classified (step = the job's name, run `ci:<id>`): `product` → fix, amend, rerun it; no change behind it (a runner or network fault) = `flake` | `gate` → its fix queued, then `gh run rerun <id> --failed`, both runs recorded. `main` CI red or GitHub unreachable → `bash tools/gate.sh` locally.
- Fresh host (gitignored paths start empty: a new clone, a remote runner): bootstrap in the same command = `bash tools/bootstrap.sh && bash tools/gate.sh`.
- Fast gate (iteration, never the claim) = `bash tools/fast-gate.sh [--e2e]`: cheap stages in parallel + incremental Lean build + tests; the engine stage runs only when `engine_key` (`tools/gate.sh`: the built engine, its loader, tests, traces + framing code) differs from its last pass's (`.lake/fast-gate/engine.key`; probe `fast_engine`); prints the stages it skipped.
- Probes = `bash tools/gate-probe.sh [probe…]` (default all; its `expect <name> <cause>` + `allow <name>` lines = the probe list): every purpose-built check plants a failing input + demands its named cause, targets restored + re-hashed after; a new purpose-built check ships its probe in the same commit. An unknown probe name or a probe function's nonzero rc fails the run (probe `dispatch`); tool helpers = `tools/probes/*.test.mjs` + `tests/tools/`, each run on the tool's own source text. Upstream tools (Lean kernel, oxlint, tsc, Prettier, stylelint, html-validate, axe, pnpm audit, betterleaks, zizmor, actionlint, shellcheck, spec-lint) carry their own suites; a config change to one of them proves firing on a planted input in its commit body.
- Engine + GUI timing + parity (outside the gate: timing needs an idle host, parity an old binary) = `bash tools/scale.sh --assert` (kernel.md P-bound + U-time: CLI, `serve`, page engine via `tools/scale-page.mjs`, GUI via `tools/scale-gui.mjs`) + `bash tools/compare.sh OLD NEW` (byte equality); law = `.claude/rules/fast.md`.
- CI: triggers = `main` + `ci/**` pushes, PRs, weekly; `gate` job (ubuntu) = one matrix entry per shard, each `tools/gate.sh --shard`; `portability` job = `build.yml` on the four release platforms (linux x86_64 + arm64, macOS arm64, Windows x86_64: `lake build` + `lake test` + the checked release archive); `release.yml` = a `v*` tag → GitHub Release (law: `release.md`); `codeql.yml` = GitHub code scanning alone (`security-extended`: javascript-typescript, actions, c-cpp = the FFI shim + the page engine bridge, compiled as `c-analyze` sees them). Every external `uses:` pinned by full SHA (in-repo calls: `$/…`), `contents: read` (CodeQL's job adds `security-events: write` for its upload, release `publish` `contents: write`), `persist-credentials: false`. Update automation = Renovate (`renovate.json`): npm, Actions digests, `lean-toolchain` + the `tools/wasm.lock` runtime line (one group), Emscripten (`tools/wasm.lock`), `tools/tools.lock` versions (digests via `tools/pin-tool.sh` | `tools/pin-wasm.sh`); release age + bump recipes = `deps.md`. Lean in CI = `tools/install-lean.sh` (elan-init pinned by sha256 in `tools/tools.lock`; every download bounded + retried, each attempt ≤ 180 s (TERM at 179 s, KILL at 180 s: a download that ignores TERM still ends; probe `install`); the step's `timeout-minutes: 10` = the outer bound, so a stalled install ends the job within minutes, not at its 60 min limit). Every job that runs `lake build` provisions Python (`actions/setup-python`) + restores the page engine's build folder from the Actions cache (law: `wasm.md` CI cache), except on the weekly scheduled run + a release build, which build it from scratch.
- Commit body records the red witness for each new test: the mutated or unfixed revision + the command + its failing output; a test pinning already-passing tested (unproved) code instead records `node tools/mutate.mjs <file>` scope + every survivor with its ruling.
