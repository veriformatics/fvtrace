# Operations

- Env: Lean per `lean-toolchain` (elan, or a system Lean of that exact version on `PATH`); `pnpm install --frozen-lockfile` (Node per `.node-version`, dev-only tooling); `bash tools/fetch-tools.sh` (betterleaks, zizmor, actionlint pinned by sha256 in `tools/tools.lock` → `.tools/bin/`); `pnpm exec playwright install chromium-headless-shell`; system `bwrap`, `shellcheck`, `jq`, `clang` (static analyzer); Python ≥ 3.10, `curl`, `tar`, `git` (the page engine build: `lake build` fetches the pinned Emscripten + Lean runtime sources into `.lake/build/wasm/` and generates Init's C once per toolchain, minutes; law = `.claude/rules/wasm.md`).
- Gate = `bash tools/gate.sh`: the ONE invocation; CI (`.github/workflows/gate.yml`) runs exactly it, one parallel job per shard (`--shard <name>`; `STAGES` atop the script gives each stage its shards; each job = a fresh checkout ⇒ every shard whose stages read the build lists `lean-build`). Stages run to completion, each `<stage> rc=N <s>s` (suites add their three slowest areas), close `gate rc=N <s>s`: `tools` (fetch) · `lean-style` · `lean-build` (every target, the page engine + `fvtrace-wasm` included; proofs kernel-checked; `warningAsError`) · `lean-test` (`lake test`) · `lean-pure` (`TestPure.lean` interpreted = the mutation tool's suite; an FFI call there aborts it) · `cli` (`tests/cli/smoke.sh`: the built binary — data folder from the environment, exit codes, nothing written outside the data folder) · `examples` (`fvtrace check --strict` on both examples) · `engine` (`node --test tests/engine/`: the exported page's WebAssembly engine, run by its loader, answers every differential case byte for byte as the native engine does; Chromium = e2e `engine.spec.js`) · `trust` (`tools/trust.sh`: `fvtrace-trust` audit (claims, axioms, escape hatches, OS capabilities) + independent-kernel replay + the self-trace's statement replays (`fvtrace verify --run`); both skipped for a key = export sha256 + `lean --version` + `tools/trust.sh` + the self-trace + `TrustMain.lean` + `tools/statement.sh` that already passed, recorded in `.lake/trust/replayed` after a pass) · `c-analyze` (`clang --analyze` on the FFI shim + the page engine bridge) · `vendor` (`tools/vendor-hacl.sh --verify`: vendored HACL* = the pinned release) · `js-format` (Prettier) · `js-lint` (oxlint typed + DOM-sink ban, stylelint, html-validate) · `js-types` (`tsc -p . | web | tests/e2e`) · `js-test` (schema ↔ decoder cases, GUI palette floors, Renovate extraction) · `e2e` (Playwright + axe against the built `fvtrace serve`) · `audit` (no Lake packages + `pnpm audit`) · `secrets` (betterleaks: history + working files) · `workflows` (zizmor + actionlint) · `fanout` (every stage has a shard; the `gate.yml` matrix = the `STAGES` shards; one `--shard "$SHARD"` step) · `spec` (`.agent/spec-lint`) · `shell` (shellcheck) · `meta` (version in `Fvtrace/Version.lean` = `lakefile.lean`).
- CI gate (template `CI gate`) = where the full gate runs while `main` CI is green: commit, then `bash tools/ci-gate.sh <unit>` (pushes `HEAD` to `ci/<unit>`, waits for that commit's run = every shard + portability, prints run id + tree + each job's wall-clock, deletes the branch when green). Red → fix, amend, rerun it; red with no change behind it (a runner or network fault) → `gh run rerun <id> --failed`, both runs recorded. `main` CI red or GitHub unreachable → `bash tools/gate.sh` locally.
- Fresh host (gitignored paths start empty: a new clone, a remote runner): bootstrap in the same command = `pnpm install --frozen-lockfile && bash tools/gate.sh`; its first run also needs `pnpm exec playwright install chromium-headless-shell` (`tools` fetches the scanners itself).
- Fast gate (iteration, never the claim) = `bash tools/fast-gate.sh [--e2e]`: cheap stages in parallel + incremental Lean build + tests; prints the stages it skipped.
- `green` = the stages run + passed; skipped, not-run + missing checks reported by name or `none`.
- Probes = `bash tools/gate-probe.sh [probe…]` (default all; its `expect <name> <cause>` + `allow <name>` lines = the probe list): every purpose-built check plants a failing input + demands its named cause, targets restored + re-hashed after; a new purpose-built check ships its probe in the same commit.
- Engine timing + parity (outside the gate: timing needs an idle host, parity an old binary) = `bash tools/scale.sh --assert` (F5 bounds) + `bash tools/compare.sh OLD NEW` (byte equality); law = `.claude/rules/fast.md`. Upstream tools (Lean kernel, oxlint, tsc, Prettier, stylelint, html-validate, axe, pnpm audit, betterleaks, zizmor, actionlint, shellcheck, spec-lint) carry their own suites; a config change to one of them proves firing on a planted input in its commit body.
- CI: triggers = `main` + `ci/**` pushes, PRs, weekly; `gate` job (ubuntu) = one matrix entry per shard, each `tools/gate.sh --shard`; `portability` job (macOS, Windows) = `lake build` + `lake test`; `codeql.yml` = GitHub code scanning alone (`security-extended`: javascript-typescript, actions, c-cpp = the FFI shim + the page engine bridge, compiled as `c-analyze` sees them). Every `uses:` pinned by full SHA, `contents: read` (CodeQL's job adds `security-events: write` for its upload), `persist-credentials: false`. Update automation = Renovate (`renovate.json`): npm, Actions digests, `lean-toolchain` + the `tools/wasm.lock` runtime line (one group), Emscripten (`tools/wasm.lock`), `tools/tools.lock` versions (digests via `tools/pin-tool.sh` | `tools/pin-wasm.sh`); release age + bump recipes = `deps.md`. Every job that runs `lake build` provisions Python (`actions/setup-python`) + restores the page engine's build folder from the Actions cache (law: `wasm.md` CI cache), except on the weekly scheduled run, which builds it from scratch.
- Commit body records the red witness for each new test: the mutated or unfixed revision + the command + its failing output; a test pinning already-passing tested (unproved) code instead records `node tools/mutate.mjs <file>` scope + every survivor with its ruling.
