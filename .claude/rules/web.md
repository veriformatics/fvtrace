# GUI

- Display only: every verdict, ranking, plan + sentence on screen comes from the engine's JSON; the GUI computes none (a re-derived judgment would sit outside the proofs).
- The address hash holds the view. A linked `whatif` spec goes to the engine unparsed (its problem is shown; the GUI then adopts the engine's normalized overrides), never repaired client-side. Served, the engine = the server's route; exported, = the WebAssembly engine in its Worker (`web/worker.js` running `web/engine.js`; the page makes it from its `fvtrace-worker` block through one Trusted Types policy, `kernel.md` E-page + E-gui; a page without WebAssembly starts none; requests go one at a time, each checked against an engine failure): the precomputed recorded envelope paints first, the engine starts before the page parses its data block (start + load posted together; `worker.js` takes messages in order; page v4's snapshot block = the engine's input text), the newest request wins (request numbers `evaluations` + `detailsAsked`: an older answer is dropped; one evaluation in flight, a newer one waits + replaces any older waiting one; an item answer asked for an earlier envelope (`generation`) is dropped), any engine failure on any request (evaluation, details, pairs) ends it for the session (recorded view + the engine notice; no further call), an older export's `#action=X` = the engine's expansion of X from the recorded view (refused X → notice). Requests = one form for both sources (`ask`: `POST /api/answer` | the page engine's `request`, kernel.md V-request): a symbol stacks or removes its fact within the shown what-if (the new fact first, at the status the engine names), an action sends its id + the shown what-if and adopts the answer's overrides, a selection asks for its details for the shown view (served: with `X-Fvtrace-View`; a 409 `view` re-evaluates first); a detail section shows the engine's lists once they arrive, nothing while pending (the inspector `aria-busy`), the engine-off line where the page's engine cannot run.
- Responsiveness (kernel.md U-*): the GUI reads one `web/lookups.js` index per adopted envelope (no card, contact or row scans an envelope list); every long list = `web/lazy.js`: an 8 ms step of rows mounts, more as an end comes within 1,500 px (the bottom end looks below the viewport, the top end above: an end the reader scrolled past stays still) or focus reaches its last rows; rows keyed + signed (an unchanged row keeps its element: identity e2e), a selection drawn apart (`markCard` / `markRow`, never in a signature), an end line says what lies beyond, nested lists (`listOf`) name position + size and key their rows so a rebuilt card remounts its focused row (`showIn`); each page-level list shows its count above it (user ruling). Body `aria-busy="true"` from each request's start (an empty value reads as false), `#working` past 1 s. The find route = `web/find.js` (entries per envelope, built on the first search; exact id → id prefix → words; Enter takes the first, its keydown cancelled; a choice selects, mounts, scrolls + focuses without the inspector's focus). Times = `tools/scale-gui.mjs` (U-time); function = `tests/e2e/responsive.spec.js`.
- DOM built with `createElement` / `textContent` / `append`; HTML-string sinks (`innerHTML`, `outerHTML`, `insertAdjacentHTML`, `srcdoc`, `createContextualFragment`, `document.write`) fail `oxlint` (`no-restricted-properties`), and the server's CSP enforces Trusted Types so a missed sink throws at runtime.
- No build step: ES modules typed by JSDoc, checked by `tsc -p web` (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`); fetched JSON stays untyped until a decoder narrows it (oxlint `no-unsafe-*`).
- Browser checks run in Playwright's bundled Chromium (it honors reduced-motion emulation, which some browsers ignore); `CHROME=<path>` overrides locally.
- e2e limits are sized for a host loaded to ≈ 2.6× its CPUs (measured there: `export.spec.js:76` 33.9 s, `smoke.spec.js` 97 s, `engine.spec.js` 110 s): default 90 s per test, setup hook + fixture teardown (`playwright.config.mjs`), `smoke` 300 s, `engine` 600 s. A limit catches hangs; changing one = a gate change, approved by the user. Evidence = `bash tools/e2e-load.sh measure <hogs>` (durations with limits lifted under a known load) + `gate <runs>` (full gates at ≥ 1.5× load); run it where the load is yours to raise.
- Palette = the custom properties atop `web/style.css` (paper, panel, ink, conductor, verified, assumption + their washes); a state shows as shape + word (lamp symbol, switch drawing, verdict text), color repeats it. `tests/palette/` (gate `js-test`) computes it: text ≥ 4.5:1 on each surface it sits on, state marks ≥ 3:1 on the panel, state hues OKLab ΔE×100 ≥ 15 unsimulated and ≥ 8 under protan + deutan (Machado); a new color or surface pairing joins its tables.
- Selectors are classes (stylelint: no IDs, specificity ≤ 0,2,1): IDs exist for JS lookups + ARIA references alone; a `hidden` section needs `.x[hidden] { display: none }` when its class sets `display`.
- Readable text stays selectable: no sentence, title or fact text inside a `<button>` (a drag there presses it, so nothing can be copied). A container that opens details = plain text + its id as the button (`idButton`, the keyboard + screen-reader route) + `clickToOpen` on the container (`web/dom.js`), which ignores a click that ends a text selection.
- `web/app.js` starts last (`readHash`, `wire`, `load` at the module's end): an exported page renders during the module's evaluation, so every `const` that `render` reads must already be initialized (a later one throws a TDZ `ReferenceError`; e2e `export.spec.js` catches it).
- `web/words.js` `verdicts` = the engine's `State.verdict`, one word per state (`Tests/Assets.lean` holds them equal). A work row's "Needed by C2, together with …" = that claim's engine `gaps` minus the row's fact: a display of engine lists, never a sufficiency judgment.
- Fonts vary by browser (the stack ends in `system-ui`, which resolves per system, e.g. to Noto Sans CJK, whose tall line box sits below its letters): an alignment check measures under ≥ 2 fonts (the default + `DejaVu Sans`, set through `document.body.style.fontFamily`). A symbol beside words centers on the words' capitals (`text-box: trim-both cap alphabetic` on the words inside a flex row), never on the line box; numbers that must line up use `tabular-nums`.
- Tour (`web/tour.js`): a card never covers its step's spotlight — e2e walks every step at 1280×720 + 390×844 (synthetic study; fixture with violated facts + a missing check). Placement = below → above → beside → shrunk into the larger free side; phones dock at the bottom; a step whose target is too tall to share the screen spotlights its `compact` part; `.tour-room` lets a page-end target scroll to the top.
