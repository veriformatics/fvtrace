# Fast paths (`.agent/contracts/kernel.md` § Performance)

- The binary answers through indexes + memos (`Answers.fast`, `Lookups.fast`, `Json.sortMembers`), each proved equal to the plain definitions the other claims are about: `Spec.AnswersAgree` (every scenario), `Spec.LookupsAgree` (every trace), `Spec.SortMembersAgree`. A change to a fast path or to a `Scenario` / `Check` definition it mirrors keeps those proofs; the self-trace cites them (C9: P10–P12), so its receipts re-pin with the proof files (`examples.md`).
- Cost traps (each measured): a `def` that returns a closure after `let`s compiles to full arity, so the let-bound index is rebuilt on every call → carry the index in a structure (`Receipt.BindingIndex`) or pass it in; `Claim.needsAll` appends on every call → once per claim (`ClaimMemo.needs`, `planOf`); a forest experiment's closure reads its parent links (`Ctx.closureWith`); a walk from a blank array of marks costs O(n) per call, so it serves single requests + experiments outside the forest alone (per experiment in the experiments shape it was n² per scenario); no closure is kept for all experiments (the chain third of prereqs held 40 M positions); a plan search asks its node answers of the same set repeatedly (the root's bound, and with one relevant experiment every costly node + the plan, = the closure of all relevant experiments) → `planOf` builds that set's delta once (`memoAt`: a claim's details on outcomes at the cap 1.49 → 0.58 s served); a claim's lists + counts each re-read every need's status by id (≈ 20 searches per need) → each need read once into a tuple list (`planOf`'s `ne`, `viewWith`'s), and an index of the needs built only when a candidate reads it (`Core.incompatible`): deep's claim details at the cap 2.55 → 0.83 s served on a laptop CPU. A `String.replace` (or `splitOn`) over the exported page after its data + engine are inlined scans every character (74 MB at outcomes' cap: half of `export --html`) → edit the small template, then inline (`Export.pageWith`).
- Proof statements that a rewrite must match name pair members by projection (`fun x => … x.1 …`): a pattern lambda (`fun (k, st) => …`) elaborates to an auxiliary matcher, and `rw` fails to match it across definitions.
- Evidence for a change here, in its commit body: `bash tools/compare.sh <binary before> .lake/build/bin/fvtrace` = 0 differing outputs + 0 timeouts (probe `compare` plants a difference + a timeout); `bash tools/scale.sh --assert` on an idle host = kernel.md P-bound + U-time, each row = its fastest of `--runs` (3) runs (every P-time row of the graded shapes ≤ 10 s at N_cap, GUI rows within their own bounds, wall + RSS ≤ 2.5× and eval bytes ≤ 2.2× per doubling (a GUI row's memory = the page's live JS memory after a forced collection: Chromium's `performance.memory` is cached + bucketed), P-memory's RSS cap; the served first view navigates the moment the server prints its link, the browser + its page made before the spawn (a page made after it lands at an uncontrolled point of the launch evaluation, and the fastest of 3 can then pick the latest landing; `scale-browser-first`); `SCALE_GUI_PHASES=<file>` appends each served first view's phases in ms (spawn → link, link → the page's time origin, answer wait, transfer, response end → painted, first); `SCALE_HOST_LOG=<file>` = `tools/scale-host.mjs` samples the host each second for the whole run (package temperature, throttle events, active-core clock, stall + memory pressure, the 3 busiest processes; its own CPU at exit) beside a mark at each run's, session's + GUI step's start + end: a slow row read against the host's state, never graded (a cause stays a lead until a run alternating its rivals separates them); probe `scale` plants each breach). Supplemental shapes report output bytes beside time: time that grows faster than the output is a scan beside it (P-bound).
- Graders fail closed, since a grader that reads a failure as a pass hides a regression behind green: a session's nonzero exit or timeout outranks every row it printed (`scale.sh` `session_row`), a failed run outranks the faster runs of its row (`fastest`, `sessions`), and a row exiting 0 without a numeric wall time fails (`no wall time`: awk compares a `-` with the bound as text); details timing runs from the click's own pending → ready transition (a reselected item still shows its old ready answer at the click); a GUI driver whose server cannot spawn ends through its cleanup; `compare.sh` compares rc + stderr beside each JSON document, and a failed parse, transform or form detection counts as a difference (two empty normalizations prove nothing). Their probes: `scale`, `compare` (helpers `tools/probes/{scale-gui,scale-spawn,compare}.test.mjs`, `tests/tools/scale-{session,runs}.sh`).
