# Server (`fvtrace serve`)

- Routes = the embedded GUI files (`FvtraceWeb.files`, byte-equal to `web/`, every `web/*.{html,js,css}` listed — `Tests/Assets.lean`) + `POST /api/answer` (body = a V-request `{whatif, action?, details?}`, ≤ `Server.bodyCap` = 16 MiB + 1 KiB, else 413, read only after access passes; answer = the envelope, the details or a problem, byte-equal to `fvtrace eval`'s, header `X-Fvtrace-View` = the view the answer read (`Session.viewOf`: trace member + bindings + replay notices, absent when none + what-if; the trace member's digest skips notices, so a notice-only write changes the view through them); a request naming another view = 409 `view`). Problems reach the GUI in its own words (`Server.problemReply`): an ill-formed or undecodable record = `recordErrors` ("The claims and facts on record have errors. To see them, run fvtrace check in the project folder."); no record = "…no claims and facts on record yet. To start, run fvtrace init…"; an unreadable one = "…cannot be read. To see why, run fvtrace check…" (user rulings 2026-11-01: each names the command to run, never a file path). No route serves project files: evidence reaches the GUI as receipts inside the envelope; a file-reading route would turn a token leak into a project-folder leak (`fvtrace-trust` holds `Fvtrace.Server` to the `network` capability alone).
- Access, decided by the pure `Server.decide` before any I/O, in this order: the method (`POST` on `/api/answer`, `GET` elsewhere: 405); `Host` ∈ the allowed names (421: DNS rebinding) = loopback: `fvtrace.localhost`, `localhost`, `127.0.0.1`, `[::1]` + the port; `--host A`: `A` (or `[A]`) + the port; the GUI files answer without a credential (open-source code, no data); `/api/answer` needs `Authorization: Bearer <token>` (403 + `{problem: {kind: "access"}}` otherwise: no unauthenticated request reaches a body, `Overrides.parse` or the trace), compared with `sameSecret` (length + byte-xor fold, no early exit). Token = 16 random bytes per run (hex), or `--token-file FILE`'s text without surrounding white space (`Cli.tokenOf`: ≥ 32 letters, digits, `-` or `_`; else exit 2 naming the file), read by `Cli.serveCmd`, never by `Server`: a proxy that logs users in sends it for them. Past the token, `Content-Type` must be `application/json` (`Server.isJson`: parameters aside, case-insensitive; 415 `invalid` otherwise): a page from another origin cannot send it without a preflight, so behind a proxy that adds the token, another site's form or `text/plain` post never reaches the engine. No cookie, set or read: cookies ignore ports, so one would reach every server on the host. No CORS header: a page from another origin cannot send `Authorization` (or a JSON body) without a preflight, and OPTIONS answers 405. `--host` takes one concrete address (a wildcard has no single `Host` name to allow).
- Bind (`Cli.serveCmd`): loopback = one port on both `127.0.0.1` and `[::1]`, since `localhost` names reach either (Chromium tries `::1` first): `[::1]` busy (`IO.Error.resourceBusy`) → refuse to serve on a fixed port (the message names `[::1]:<port>`), under `--port 0` shut the IPv4 listener + take another free port (bounded attempts); `[::1]` unsupported (`unsupportedOperation`: no IPv6) → IPv4 alone. Default port 8718 (U+220E ∎; the help leaves the easter egg unsaid).
- Link = `http://fvtrace.localhost:<port>/#token=<token>` (`--host`: the address): the `#` part never reaches a server, a log or a `Referer`. `serve` opens it itself unless `--no-browser`, `--host`, an SSH session (`SSH_CONNECTION` | `SSH_TTY`), WSL (`WSL_DISTRO_NAME`) or, on Linux, no display (`DISPLAY` + `WAYLAND_DISPLAY` unset): it writes a redirect page into `<data folder>/serve/` (folder set to mode 0700 on every run, before the write) and runs the platform opener (`xdg-open` | `open` | `explorer.exe`) with that file's path as its one argument — a link on a command line shows in every user's process list. Opened → prints the address, then the link as a fallback line: an opener's exit 0 does not prove the page loaded (a Snap browser cannot read hidden folders; macOS may hand HTML files to another app). Not opened or the opener failed → prints `Open <link>`. `--token-file` → no opener, no link: prints `Serving <address> with the token in <file>.` (a service's output lands in logs; the operator holds the file).
- GUI (`web/app.js`, served mode): takes `token` from the address once, removes it before `readHash` or any `pushState` (`history.replaceState`, the other hash parameters kept, so no history entry keeps it), keeps it in `localStorage` (one origin = one port) once fvtrace admits it (200, 400 or 409: answers past the access check; a 400 what-if problem counts), sends it on every evaluation request. Credentials per request (`ask`), each once, in order: the address token (offered to every request that starts before the first settles), the stored token, none — no `Authorization` header, so the browser's own login (HTTP Basic) reaches a proxy that adds the token (`--token-file`); 401 (a login proxy refused the request; fvtrace never answers 401) or 403 (fvtrace refused the token) moves on; a refused stored token is forgotten (`forgetToken`: only while storage still holds that token, since another tab may have stored a newer run's), a refused address token leaves the stored one (another site may link `#token=junk`). e2e `proxy.spec.js` (Basic login + path + token added) covers the three paths. Requests go to `api/answer` relative to the page: a proxy may serve the GUI under a path (`/fvtrace/`, prefix stripped).
- Every response carries `fixedHeaders`: CSP `default-src 'none'` + `'self'` scripts/styles/connect, `frame-ancestors 'none'`, `require-trusted-types-for 'script'; trusted-types 'none'` (HTML-string sinks throw), `nosniff`, `no-referrer`, COOP/CORP same-origin, `no-store`.
- The port (so the hosts) is known only after binding (`--port 0`), so `Server.Config` sits in an `IO.Ref` filled after `Server.start`; a request before that meets an empty host list.
- e2e (`tests/e2e/fvtrace-server.js`) runs the built binary: temp `FVTRACE_HOME` + project with the synthetic study pinned, `serve --port 0 --no-browser`, the printed link (tests append view parameters with `&`: the link ends in `#token=…`); `serveFvtrace`'s `extra` adds flags made in the run's folder (`--token-file`: the printed address, no token). `lean-build` must precede `e2e`.
